# axiom3d v1 (walk slice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP server and CLI that let any AI model animate a humanoid mannequin through anatomy-level controls. The tool does the math, grades the model's predictions, and certifies a walk only when it passes the checks.

**Architecture:** A pure-Python core: numpy math, a rigid-segment skeleton with forward kinematics and analytic leg IK, and a clip of keys plus foot constraints solved live at each frame. Measurements, checks and the predict-and-grade protocol sit on top. `api.Workbench` holds all behaviour; `mcp_server.py` and `cli.py` are thin wrappers. Session state is an ordered command log replayed on load.

**Tech Stack:** Python ≥3.11, numpy, Pillow, mcp 2.x (`mcp.server.mcpserver.MCPServer`), pytest, uv.

**Spec:** `docs/superpowers/specs/2026-10-24-axiom3d-design.md`

## Global Constraints

- Runtime dependencies are exactly `numpy`, `Pillow`, `mcp>=2.3,<3`. The only dev dependency is `pytest`. Run everything with `uv run`.
- World frame: right-handed, Z up, metres, angles in degrees.
- Heading: 0 means facing −Y with the character's left at +X. Positive heading turns the character left (counter-clockwise seen from above).
- Quaternions are numpy `(w, x, y, z)` internally and `(x, y, z, w)` only inside glTF.
- The anatomy sign table in the spec is the contract. Tests pin it through FK, never by restating the axis constants.
- **Track frame:** every positional command argument (`forward`, `left`) is measured from the task's start root ground point, along the task's start heading.
- Never `eval` or `exec` model input. Every model-facing failure is an `AxiomError` with an actionable message, never a traceback.
- Same session commands in, same text and bytes out. The only randomness is seeded from the session id.
- Exactly 13 MCP tools: `start_session, answer_quiz, guide, observe, check, set_root, set_pose, plant_foot, swing_foot, undo, accept_discrepancy, finish, export`.
- Protocol on or off is fixed when the server starts (`axiom3d serve --protocol off`) or per CLI `call start_session --protocol off`. It is **never a tool argument**, so a model can't switch it off to skip the quiz.
- Commit after every task to `claude/vigilant-goodall-y4x0bf`, with the session trailer lines.

**Deviations from the spec, decided here:**
1. Root position, heading and pose channels interpolate **linearly**, per channel, instead of cubic Hermite and slerp, so a model can compute in-between values exactly.
2. The walk task is `walk_forward`: start and end standing, no loop. Swings can't cross the loop boundary in v1. The `gait.loop_continuity` check still ships and runs only when `timeline.loop` is set.
3. `turned_step` became `turn_then_step`: turn to heading 90, then step along the new facing, which is the track's +left axis. This makes the frame conversion real.
4. The spec's EXAM phase is transient inside `finish`. Stored phases are `BRIEFING | WORKING | DONE`.

## Review Focus

1. **A model sends wrong names or values**: `hip_left`, `L_hip.flex`, frame 99, angle `"30"`. Expect an `AxiomError` that names the valid choices. Pinned in Task 13.
2. **Prediction text variants**: `+-`, `+/-`, `±`, a Unicode minus `−`, uppercase, extra spaces. They must parse the same. Pinned in Task 10.
3. **Unknown or corrupt session**: missing id, unknown id, broken JSON. Expect a clear error saying to call `start_session`. Pinned in Task 12.
4. **Calls in the wrong phase**: an edit before the quiz or after DONE, `answer_quiz` in bare mode, `finish` while a discrepancy is pending. Expect a message stating the required next step. Pinned in Task 13.
5. **Degenerate geometry**: an IK target at the hip, a zero-length swing, overlapping plants on one side, a swing with no plant on one side. Expect no NaN, plus a `CommandError` or a note. Pinned in Tasks 3 and 4.

### Task 3: Analytic leg IK

**Files:** Create `axiom3d/rig/ik.py`. Test: `tests/test_ik.py`.

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces:
  - `@dataclass LegIKResult(hip_local: quat, knee_flexion_deg: float, ankle_dorsiflexion_deg: float, reached: bool, shortfall_m: float)`
  - `solve_leg(skel, side, pelvis_position, heading_deg, ankle_target) -> LegIKResult`

**Algorithm** (not determined by the tests). `a`/`b` = thigh/shank, `d` = target − hip, `L` = |d|.
1. Clamp `L` to `[|a−b|+1e-6, a+b]`. `reached` = the unclamped L ≤ a+b+1e-6 (and ≥ the minimum). `shortfall` = the excess.
2. Find `p` = the character forward at `heading_deg`, made perpendicular to `dir = d/L`. Fallback: the character left × dir.
3. Compute `α = acos((a²+L²−b²)/(2aL))`. Then:
   - the thigh direction `t = cosα·dir + sinα·p`
   - the knee forward `f = −sinα·dir + cosα·p`
   - hip world frame columns `X = f×t`, `Y = −f`, `Z = −t`, so `hip_local = conj(heading_quat) ⊗ matrix_to_quat([X Y Z])`
4. `knee_flexion = 180 − deg(acos((a²+b²−L²)/(2ab)))`.
5. Foot flat: `q = conj(knee_world_rot) ⊗ heading_quat`. Take its twist about +X, `θ = 2·atan2(q.x, q.w)`, giving `dorsiflexion = −θ`, clamped to the limits.

### Task 4: Clip, commands, evaluation, reference solutions

**Files:** Create `axiom3d/anim/clip.py`, `axiom3d/anim/commands.py`, `axiom3d/anim/evaluate.py`, `axiom3d/tasks/reference.py` (the plain command lists given in Task 6). Test: `tests/test_clip.py`.

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces from `clip.py`:
  - `Timeline(fps=24, start=0, end=24, loop=False)`
  - `RootKey(frame, position: tuple3|None, heading_deg: float|None)`
  - `PoseKey(frame, channel, value_deg)`
  - `Plant(side, start, end, xy: tuple2)` (world)
  - `Swing(side, start, end, apex_m)`
  - `Clip(timeline, track: TrackFrame, root_keys, pose_keys, plants, swings)` with:
    - `root_at(frame, rest_height) -> (position np(3), heading_deg)`: position and heading interpolate linearly and independently over the keys that set them. Values hold before the first key and after the last. Defaults are `(origin, rest_height)` and `track.heading_deg`.
    - `channel_at(channel, frame) -> float`: linear interpolation, holding at the ends, 0 when there are no keys.
- Produces from `commands.py`: `CommandError(ValueError)` and `apply_command(skel, clip, cmd: dict) -> Clip`, which returns a new clip.

  | Op | Arguments | Behaviour |
  |---|---|---|
  | `set_root` | `frame, forward?, left?, height?, heading?` | Unspecified fields keep the evaluated value at that frame; forward/left are track coordinates. Writes one RootKey with full position, plus heading only if given. |
  | `set_pose` | `frame, angles: {channel: deg}` | Replaces keys with the same frame and channel. |
  | `plant_foot` | `side, start, end, forward?, left?` | Track coordinates converted to world xy at command time. `left` defaults to ±`hip_half_width`, `forward` to 0. |
  | `swing_foot` | `side, start, end, apex=0.08` | |

  Errors:
  - unknown op, side or channel (the message lists the valid channels)
  - a frame outside the timeline
  - start ≥ end
  - same-side plant/plant or swing/swing overlap, or a plant/swing interior overlap (sharing an endpoint frame is allowed)
  - a non-numeric value
  - apex outside [0, 0.3]
- Produces from `evaluate.py`:
  - `@dataclass FrameState(frame, root_position, heading_deg, rotations, joint_world, points, angles: dict[channel, deg], leg_modes: {"left"|"right": "plant"|"swing"|"keys"}, ik: {side: LegIKResult|None}, notes: list[str])`
  - `evaluate_frame(skel, clip, frame) -> FrameState`
  - `evaluate_clip(skel, clip) -> list[FrameState]`, covering every frame from start to end inclusive

**Evaluation rules:**
1. A plant covering the frame wins over a swing on the same side.
2. A plant puts the ankle target at `(xy, ankle_height)`.
3. A swing's target interpolates between the xy of the plant ending at or before `start` and the plant starting at or after `end`, with `t = (f−start)/(end−start)` and `z = ankle_height + apex·4t(1−t)`.
4. If a swing has no plant on one side, the leg falls back to keys and gets a note `"left swing 6-18 has no plant before/after; using keys"`.
5. On IK-driven legs, keys for that leg's hip, knee and ankle channels are ignored, with one note per channel.
6. Non-finite points raise `RuntimeError`.

|---|---|---|

### Task 10: Prediction language

**Files:** Create `axiom3d/protocol/predict.py`. Test: `tests/test_predict.py`.

**Interfaces:**
- Consumes: Tasks 4–5.
- Produces:
  - `PredictionError(ValueError)`
  - `@dataclass Prediction(text, kind: "compare"|"relation"|"metric", ...)`
  - `parse_prediction(text, skel) -> Prediction`
  - `is_precise(p) -> bool`
  - `evaluate_prediction(p, skel, clip, states, default_frame) -> Outcome(passed: bool, measured: str)`

**Grammar** (case-insensitive; normalise `−`→`-`, `+-`/`+/-`→`±`, and collapse spaces first):
- **Subjects:**
  - `<point>.(x|y|z|height|forward|left)`: forward/left are track coordinates
  - `root.(x|y|z|height|forward|left|heading)`
  - `<channel>`, e.g. `left_hip.flexion`
- **Comparisons:** `subj (<|>|<=|>=) num`, `subj ~= num ± tol`, `subj in [a, b]`, `subj (<|>) subj`.
- **Relations:** `<point> (in_front_of|behind|left_of|right_of|above|below) <point>` in the character frame; `<point> on_ground`.
- **Metrics:** `(slide|min_height|max_height)(<point>) op num`, where slide is the max xy drift over the frames.
- **Frames:** an optional suffix `@N`, `@A..B` or `@all`. A range means "holds at every frame", except metrics, which aggregate. With no suffix, comparisons and relations use `default_frame` and metrics use the whole timeline.
- **Precise:** `~=` with tol ≤ 0.15 m (≤ 20° for channels and heading); `in` with width ≤ the same limits; any relation; `slide(...) <= / < v` with v ≤ 0.05.
- **Errors:** unknown names list the 10 closest valid names (`difflib`).

**Edit flow** (shared private `_edit`):
1. Protocol mode and phase BRIEFING → `AxiomError("Pass the briefing quiz first: call answer_quiz.")`.
2. Phase DONE → `AxiomError("Session is finished; start a new one.")`.
3. A pending discrepancy → `AxiomError` naming `undo` and `accept_discrepancy`.
4. Protocol mode: parse `expect`. If it's missing, or nothing in it is precise, raise `AxiomError` with a worked example and increment `rejected_edits`.
5. Apply the command. `CommandError` / `PredictionError` → `AxiomError(str(e))`.
6. Rebuild and grade the predictions at the command's frame (the end frame for plant/swing). Update the ledger. On any failure set `pending_discrepancy`.
7. Save.
8. The text gives `APPLIED …`, a PASS/FAIL table with measured values, and the error/warning counts from `run_checks`.

**Other rules:**
- In protocol mode every text ends with `STATUS: phase=<P> · errors=<n> · warnings=<m> · <NOT COMPLETE|CERTIFIED>`.
- In bare mode, `expect` is ignored and hints are left out of check and report output.
- `observe` views are `report` (default), `timeline` (default), `sheet`, `filmstrip` and `footprints`; image views add PNGs to `images`. Frames default to `[end]`, and the filmstrip uses 8 evenly spaced frames.
- `finish` bumps `exam_attempts` and records `task_success`.
  - Protocol mode: pass → DONE and `certified=True`; fail → stays WORKING, with a report of what failed.
  - Bare mode: always DONE, with `certified=None`.
- `answer_quiz` in bare mode raises `AxiomError("No quiz in bare mode.")`. A pass moves the phase to WORKING; feedback covers the wrong answers only.
- `start_session` text gives the session id, the conventions, the goal and criteria, the tool workflow, then the quiz questions (protocol mode only).
